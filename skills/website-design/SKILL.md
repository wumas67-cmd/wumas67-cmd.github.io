# website-design

## Purpose
Design polished, practical websites with strong visual hierarchy, responsive behavior, usability, and maintainable frontend code. Use this skill together with the project's existing HTML/CSS/JavaScript structure.

## Design principles
- Start from the user's business goal and content, not decoration.
- Keep the interface visually calm, clear, and trustworthy.
- Establish a consistent hierarchy for brand, navigation, hero content, products, supporting information, and footer.
- Prefer whitespace, balanced typography, and a restrained visual system over excessive effects.
- Design for mobile, tablet, and desktop.

## Layout
- Use clear sections with purposeful spacing.
- Keep primary actions visually prominent.
- Avoid overcrowded navigation and excessive card density.
- Use consistent container widths and alignment.
- Keep important content above the fold when practical, while avoiding cramped layouts.

## Typography
- Use a small, consistent type scale.
- Maintain readable font sizes and line heights.
- Keep text widths comfortable for reading.
- Use emphasis sparingly.

## Components
For commerce or product showcase sites, prefer reusable patterns for:
- header and navigation
- hero section
- product cards
- category or feature sections
- product detail summaries
- cart drawer or cart panel
- testimonials or trust indicators
- FAQ
- footer

## Interaction
- Use subtle transitions that support understanding.
- Provide clear hover, active, and focus states.
- Avoid animations that delay access to content.
- Ensure menus, cart controls, quantity controls, and forms remain usable on touch devices.

## Accessibility
- Preserve keyboard access.
- Use semantic HTML.
- Provide meaningful labels and alt text.
- Maintain sufficient visual contrast.
- Do not communicate important states using color alone.

## Performance
- Keep JavaScript lightweight.
- Optimize image usage and avoid unnecessarily large assets.
- Avoid importing large frameworks for simple static interactions.
- Keep the page usable even if optional enhancements fail.

## GitHub Pages workflow
- Inspect the repository before making changes.
- Reuse current files and styles when they are sound.
- Keep all generated frontend code compatible with GitHub Pages unless the user explicitly requests a different deployment target.
- Do not place credentials, secrets, payment keys, or private customer data in repository frontend files.

## 一縷清香 design direction
For this project, aim for a refined, warm, natural incense brand aesthetic:
- calm and elegant visual rhythm
- natural material feeling
- generous whitespace
- clear product photography areas
- easy-to-read product names and prices
- obvious but tasteful cart actions
- strong mobile usability
- avoid flashy marketplace-style clutter

## Execution standard
When the user requests a site change:
1. Read the current implementation.
2. Preserve correct existing functionality and content.
3. Improve only the areas necessary for the request.
4. Keep the design coherent with the rest of the site.
5. Verify responsive behavior and interaction flow.
6. Commit with a concise description of the change.
